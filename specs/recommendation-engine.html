recommendation engine

how trove should learn your visual taste and feed you more of it — synthesized from 4 parallel deep-research agents on photo recommendation systems.

spec · 2026-06-06 · single user · CLIP embeddings · Unsplash keyword corpus · Node/no-GPU

00why the current recs feel dead

  • One averaged taste vector. Liking moody-dark + bright-minimal averages to grey mush that matches neither. Every source names this the #1 failure mode — Pinterest's PinnerSage exists specifically to fix it.
  • We rank a random pool. Pinterest's magic isn't ranking — it's retrieval (fetching things already near your taste). We skip it.
  • No diversity control → near-duplicate spam. No negatives → skips are ignored. No persistence → the pool resets every session.

01the architecture (4-agent consensus)

The same skeleton as Pinterest, collapsed to one user, a keyword-only corpus, and plain vector math:

piecewhatsource
Multi-prototype tastek-means liked embeddings → 3–6 cluster centroids. Score a candidate by MAX cosine to any centroid — never the mean.PinnerSage, MIND, ComiRec
Rocchio negativesmaintain a dislike centroid from skips; score = maxProtoCos − γ·dislikeCos, γ≈0.3 (positives ~5× negatives).Rocchio '71 / Stanford IR
Shrinkagetrust immature clusters less: weight each prototype by w/(w+3).cold-start regularization
MMR diversitygreedy rerank, λ·Rel − (1−λ)·maxSimToPicked, λ≈0.7. + cull near-dups (cosine>0.93).Carbonell & Goldstein '98
Persistent corpussave every fetched candidate's embedding to disk. Pool grows forever; ranking is offline & free.the key retrieval insight
taste → text queriesCLIP zero-shot vs a cached aesthetic vocabulary, per cluster, polished by Claude. Turns a vector into search keywords.CLIP zero-shot / CLIP-Interrogator
ε-greedy exploredecaying 0.30→0.10 floor; explore picks woven in. Adjacent (medium-distance) queries fight the bubble.bandits / serendipity
recency decayexponential half-life (~90 days) on prototype weights; prune faded clusters.time-aware CF
The killer insight: the 50 req/hr limit only hurts if every session is cold-start. Persist every fetched image's CLIP embedding — image-byte fetches don't count against the limit, only JSON API calls do. Over days you accumulate thousands of rankable images and ranking becomes free & offline. Architect for accumulation from day one.

02the scoring function

// embeddings are L2-normalized → cosine = dot product
prototypes = weightedKMeans(likedEmbeddings, K=clamp(round(sqrt(N/2)),2,6))
dislike    = mean(skippedEmbeddings)   // once ≥5 skips

score(x):
  pos = max over prototypes of  cos(x, p.centroid) * (p.weight/(p.weight+3))   // shrinkage
  neg = dislike ? 0.3 * cos(x, dislike) : 0
  return pos - neg

feed = MMR(scored, λ=0.7)            // diversity rerank
       with ~20% ε-greedy explore picks woven in

03retrieval: taste → keywords → growing corpus

per cluster centroid:
  tags = topK( cos(centroid, cachedVocabTextEmbeddings) )   // CLIP zero-shot, free
  + Claude polishes tags + thumbnails → clean Unsplash queries
fetch (only NEW queries, rate-budgeted) → persist {id, url, embedding}
+ ~20% adjacent/exploratory queries (medium-distance tags, random endpoint)
rank the ENTIRE accumulated corpus offline → MMR → deck

04build order

1
Persistent corpus + MMR + near-dup cull. Biggest immediate win — diverse feed from a pool that grows.
2
Multi-prototype + shrinkage. Already have facets (k-means); add max-scoring + shrinkage. Kills muddy-mean.
3
Rocchio negatives. Dislike centroid from skips, subtracted in scoring.
4
taste→text via CLIP zero-shot vocab (+ fix facet labeling to use display-size images, not full-res — the current bug).
5
ε-greedy + keep-rate gauge. Exploit-vs-explore keep-rate = built-in proof it learns.
6
Recency decay. Last — only matters across sessions.

05measuring "did it get better?"

No ground truth, but a clean signal: every deck mixes model-picked (exploit) and random (explore) cards. If exploit keep-rate > explore keep-rate, the model is adding real value. A free, continuous, single-user A/B. Plus rolling keep-rate over the last 20 cards should trend up.

06what to skip

  • Two-tower + ANN (HNSW/Faiss) — pointless without owning a corpus.
  • GCN/PinSage, transformers (PinnerFormer) — need a graph + GPU + millions of users.
  • DPP — MMR gets 90% of the diversity benefit at 10% of the complexity.
  • Online logistic regression / LinUCB — viable upgrade later; the multi-prototype centroid model converges faster and is debuggable at small N.
