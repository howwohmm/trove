stack playbook

trove · deep-research across the actual stack docs (Next.js · Node · transformers.js · Claude · OpenRouter/Gemini · Unsplash), mapped to our open problems · 2026-06-07

The headline: migrate the data layer to node:sqlite (kills the critical data-loss bugs for free, no native binary), cut Claude + image-gen cost ~50–60% (you're near budget), and unlock the taste→keyword retrieval + aesthetic scoring the personas wanted — all confirmed against primary docs. The fire-and-forget pattern is fine (we're long-running Node, not serverless). Three new bugs found en route.

critical · data stop losing data

Migrate JSON stores → node:sqlite

Node 25 built-in · lib/store.ts, embeddings.ts, corpus.ts, facets.ts, dreams.ts

A single SQLite BEGIN…COMMIT makes C1 (lost updates) and C3 (torn writes) vanish by construction — atomic + isolated transactions. It's compiled into Node (no npm install, no .node file to corrupt → dodges the truncated-binary scare). WAL + synchronous=FULL, embeddings as BLOB rows (no more 8MB full-file rewrite per embed), built-in backup().

Do: one data/trove.db, transaction per keep, embeddings as Float32Array BLOBs, in-JS cosine (no vector index needed at this scale).

Hotfix path (if migrating later)

async-mutex + write-file-atomic

Wrap the whole keep (recordSwipe+addToLibrary+updateTaste) in ONE mutex.runExclusive = single read + single write. Use write-file-atomic (temp+rename+fsync). And fix the loader's catch → EMPTY to fall back to a .bak instead of silently wiping everything.

cost · you're near budget ~50–60% cheaper

Merge describe + decide into ONE Claude call

lib/claude.ts · runs on every kept image

decide reads nothing new from the image — fold worth/score/reason into the describe schema. Halves per-image calls. Biggest single lever.

Batch API for the describe pass → flat 50% off

messages.batches · dreamTick is already a background queue

Do: submit describe(+decide) as a batch keyed by item.id. Stacks with the merge → ~75% cheaper than today's two synchronous calls.

Structured Outputs — delete the fragile parseJson

output_config.format · Haiku/Sonnet both support it

Grammar-constrained valid JSON. Removes the indexOf("{") hack and silent parse failures. (Clamp numeric ranges in TS — schema can't enforce 0–1.)

BUG + cost: image-gen fixes

lib/generate.ts

Seedream slug is wrong (bytedance/seedream-4.5 → bytedance-seed/seedream-4.5, currently 404s). fal/Together fallbacks silently drop the reference images (your core quality lever). Cost: image_size 2K→1K = 33% cheaper; cap refs to 3–4; Seedream 4.5 = $0.04 flat & takes refs → best value default while credits are tight.

Native OpenRouter fallback + credit guard

openrouter docs

Do: send models:[nano-banana-2, seedream-4.5, flux.2-pro] + provider:{sort:"price"} in one request (keeps image-conditioning on every fallback, unlike the fal path). Gate on GET /api/v1/key limit_remaining before generating.

Fix the O(n²) qualities blob; skip prompt caching

lib/dreams.ts decide loop

existingQualities is recomputed + resent every decide call → quadratic token growth as the library grows. Compute once / use embedding-dedup instead. Prompt caching is a no-op on Haiku (4,096-token floor > our prompts) — don't bother. Tighten max_tokens (output is 5× input price).

quality · the personas' wishlist

Switch CLIP pipeline → explicit vision+text projection classes

lib/embed.ts · CLIPVisionModelWithProjection + CLIPTextModelWithProjection

The image-feature-extraction pipeline's CLIP routing is fragile (broke in a past version). Explicit classes guarantee image & text land in the SAME 512-d space — which unlocks taste→keywords: embed an aesthetic vocab once, score vs the taste centroid by cosine → real retrieval queries (the CTO's "interests as shared vocabulary").

LAION aesthetic score = one dot product (≈free)

sa_0_4_vit_b_32_linear · matches our 512-d vectors

A single linear head on the CLIP vectors we already compute. Dump weights to JSON, dot(emb, W)+b → a quality signal to blend into ranking + the decider. Zero new deps.

Unsplash grid: urls.raw + imgix params (60–80% smaller, FREE)

unsplash imgix · CDN bytes don't count vs rate limit

Do: urls.raw + auto=format,compress&fit=clip&w=COL&dpr≤2&q=45-60 (preserve ixid). Ships exactly column-width AVIF/WebP instead of fixed 1080px JPEG. Cold-start from /topics (curated) not /photos/random.

SigLIP2 — flagged future upgrade

onnx-community/siglip2-base-patch16-224-ONNX

Beats CLIP ViT-B/32 on retrieval (our use case). 768-d, slower, needs re-embedding the corpus + padding:"max_length". One config constant; do it after taste→keywords ships.

polish · correctness & perf

The race is real, but fire-and-forget is safe

Next.js long-running Node, not serverless

scheduleDream/scheduleFacets/warmEmbeddings complete fine on our Node server (the "Next kills background work" warning is serverless-only). The actual bug is store.ts (fixed by the sqlite migration). Wrap triggers in after() for future-proofing + add observability (replace silent .catch(()=>{}) with logged failures surfaced in /status).

next/image in the feeds + Unsplash remotePatterns

Sharp is already installed → optimizer works. Convert library/dreams masonry to <Image fill sizes…> (lazy, AVIF, blur). Leave the swipe deck on raw <img>. Drop redundant force-dynamic (handlers are uncached by default).

Turbopack stale-CSS = confirmed bug

Set experimental:{turbopackFileSystemCacheForDev:false} (likely fixes it) or use next dev --webpack during design work.

Unsplash production compliance

We're non-compliant: missing the download_location trigger on save + UTM attribution. Needed for the 5,000/hr production tier (worth applying — low effort). Add Pexels as a 2nd corpus source (200/hr, free-unlimited w/ attribution).

recommended build sequence

  1. Data: migrate to node:sqlite — protects your 190+ keeps. Everything else builds on a trustworthy store.
  2. Cost: merge describe+decide + Structured Outputs + batch + fix gen bugs (seedream slug, refs-on-fallback) + drop to 1K — keeps you generating without running out of credit.
  3. Quality: explicit CLIP classes → taste→keyword retrieval + LAION aesthetic score + imgix grid URLs — the persona wishlist, makes recs sharper and the feed lighter.
  4. Polish: after()+observability, next/image, turbopack flag, Unsplash compliance/Pexels.
